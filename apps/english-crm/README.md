# Lingua CRM — прототип CRM для онлайн-школы английского

Демо: `/english-crm/` на сайте. Все данные вымышлены и хранятся только в браузере.

## Стек и почему

- **React 19 + TypeScript + Vite + Tailwind CSS 4.** Сборка — статические файлы для GitHub Pages, без сервера.
- **Иконки:** lucide-react, один набор.
- **Шрифт:** Inter, подключён из пакета и лежит рядом со сборкой. Внешних запросов нет.
- **Графики** нарисованы своими компонентами на div/SVG — без тяжёлых библиотек.

## Структура

```
src/
  domain/   types.ts — сущности; labels.ts — подписи статусов, каналов, ролей
  data/     store.ts — хранилище (интерфейс Repository + LocalRepository)
            actions.ts — все действия пользователя (заявка, пробный, оплата, перенос…)
            selectors.ts — вычисления: остаток уроков, долги, «горящие» заявки, свободные окна
            seed.ts — демо-данные (детерминированные, от текущей даты)
  lib/      форматирование дат и денег, маска телефона, ссылки на мессенджеры
  ui/       кит компонентов: кнопки, бейджи, карточки, модальные окна, шторки, тосты
  app/      каркас, роли и права, глобальный поиск, все окна действий
  screens/  Сегодня, Заявки, Расписание, Напоминания (календарь), Ученики и группы, Оплаты,
            Отчёты (школа + зарплаты преподавателей), Настройки
```

**Замена хранилища на API.** Нужно реализовать `Repository` (`load / save / clear`), а действия из `data/actions.ts` превратить в запросы к серверу. Экраны работают через `useDB()` и `actions` и при этом не меняются.

**Остаток уроков не хранится, а считается:** купленные занятия минус списанные.
- Списываются «был» и «не был».
- «Уважительная» не списывается.
- Отменённые и перенесённые занятия не списываются.

Поэтому остаток не может разъехаться с посещаемостью.

## Модель данных

| Сущность | Ключевые поля | Связи |
|---|---|---|
| Lead (заявка) | имя, телефон, канал, источник, статус, причина отказа, история | → пробное занятие, → ученик после оплаты |
| Student (ученик) | уровень, статус (учится / пауза / ушёл), заметки | → плательщик, → группы, → абонементы |
| Payer (плательщик) | имя, телефон, кем приходится | ← ученики (родитель платит за ребёнка) |
| Group (группа) | уровень, дни и время, вместимость, ссылка на созвон | → преподаватель, → ученики |
| Teacher (преподаватель) | цвет, ставки (группа / индивидуально), рабочие часы | ← группы, ← занятия |
| Lesson (занятие) | тип (группа / индивидуально / пробный), время, статус, серия | → группа / ученик / заявка, → преподаватель |
| Attendance (посещаемость) | был / не был / уважительная | хранится в занятии: ученик → отметка |
| Subscription (абонемент) | число занятий, цена, дата | → ученик, → платёж, → тип пакета |
| Payment (платёж) | сумма в ₽, способ (наличные / СБП / перевод / карта) | → ученик, → плательщик, → абонемент |
| Task (напоминание) | текст, дата и время, выполнено | → заявка или ученик, → сотрудник |
| MessageTemplate (шаблон) | текст с переменными `{имя} {дата} {время} {сумма} {уроков} {школа}` | — |

**Воронка:** Новая заявка → Связались → Назначен пробный → Пробный прошёл → Ждём оплату → Оплатил. Из любого этапа можно уйти в «Отказ», причина обязательна.

На доске четыре колонки: Новые, Связались, Пробный (назначен и прошёл), Ждём оплату. Чтобы закрыть заявку, её перетаскивают вниз, на «Оплатил» или «Отказ», либо нажимают кнопку в карточке.

**Простота для новичка:**
- тема по умолчанию светлая;
- все суммы в рублях;
- в меню шесть рабочих разделов, «Отчёты» и «Настройки» отделены;
- на «Сегодня» есть подсказка из трёх шагов, её можно скрыть.

## Что нужно для реальной эксплуатации

- **Бэкенд и база:** сервер (например Node/PHP + PostgreSQL/MySQL) и `ApiRepository` вместо localStorage.
- **Авторизация и права на сервере:** входы сотрудников и проверка прав на сервере, а не только в интерфейсе.
- **152-ФЗ для учеников из РФ:**
  - хранение персональных данных на сервере в России;
  - согласие на обработку и политика конфиденциальности;
  - уведомление в Роскомнадзор;
  - журнал доступа.
- **Приём заявок:** форма на сайте и бот в Telegram, которые пишут заявку прямо в CRM.
- **Мессенджеры:** WhatsApp по номеру поддерживает готовый текст (wa.me), Telegram — нет, поэтому текст копируется в буфер. Отправка сообщений из CRM без участия человека требует официальных API (WhatsApp Business, Telegram-бот).
- **Резервные копии,** экспорт, история изменений.
